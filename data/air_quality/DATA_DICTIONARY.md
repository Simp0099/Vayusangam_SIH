# OpenAQ station-hour data dictionary

This dictionary describes the normalized CSV generated by `scripts/data_collection/openaq/`. Raw API response bodies are cached unchanged beneath `data/air_quality/raw/`; the raw folder is excluded from Git because it can grow substantially. No API key is written into a raw file or log.

## Provenance and scope

- Primary source: OpenAQ API v3, queried with the official `X-API-Key` request header.
- Location search: India (`iso=IN`) plus the configurable WGS84 bounding box in `OPENAQ_BBOX`. Default `74.0,26.0,80.0,32.5` covers Delhi NCR and adjacent north-west source areas; this is regional, not worldwide.
- Measurements: precomputed hourly means from `GET /v3/sensors/{sensor_id}/hours`, fetched in monthly chunks with pagination.
- `timestamp` is the UTC start of the returned hourly interval (`datetimeFrom.utc`), rounded down to the hour. Timezone is always UTC in the output.
- Each output row is unique on `station_id + timestamp`; requested hours with no measurements remain explicit `NaN` rows for every station included in that run.
- One sensor per station and parameter is selected for the wide table: greatest declared overlap of `datetimeFirst`/`datetimeLast` with the requested period, then deterministic ID order. All discovered sensors remain documented in `sensor_metadata.csv` and in the raw sensor responses.
- `station_id` is OpenAQ's location ID. `station_name`, coordinates, provider, owner, monitor status and timezone come from the location resource.
- District uses an explicit OpenAQ administrative field when present. Exact locality aliases are used only for Gurugram/Gurgaon, Noida, Ghaziabad and Faridabad. Otherwise `district` is blank. For reproducible point-in-polygon mapping of Delhi and ambiguous localities, add the Survey of India administrative-boundary shapefile (district-level geometry) and join district names/codes against the Ministry of Panchayati Raj's Local Government Directory (LGD). The Survey of India lists district-level administrative boundaries in its [official vector data catalog](https://onlinemaps.surveyofindia.gov.in/AboutPortal.aspx); the Government of India's [LGD district dataset](https://data.gov.in/resource/local-government-directory-lgd-districts) supplies district codes/names. Record the boundary vintage because districts can change. No district is guessed from a station name.
- `source_provider` identifies the OpenAQ provider. Provider/owner/instrument names and `isMonitor` are retained for station review and priority ordering; these fields alone are not an independent audit of reference-grade quality.

## Variables and units

| Output variable | OpenAQ parameter names accepted | Original unit | Final unit | Conversion | Missing / unsupported-unit behavior |
|---|---|---|---|---|---|
| `PM2.5` | `pm25` | As returned per sensor | µg/m³ | µg/m³ unchanged; mg/m³ × 1000 | Unknown units, null source values, and invalid values remain NaN; issue counts go to `data_quality_report.csv`. |
| `PM10` | `pm10` | As returned per sensor | µg/m³ | µg/m³ unchanged; mg/m³ × 1000 | Same as PM2.5. |
| `NO2` | `no2` | As returned per sensor | ppb | ppb unchanged; ppm × 1000 | Mass concentration (for example µg/m³) is not converted to ppb because a temperature/pressure basis is required; that value becomes NaN in the normalized CSV and is counted as unsupported. Raw value remains in raw JSON. |
| `NOx` | `nox` only | As returned per sensor | ppb | ppb unchanged; ppm × 1000 | NO₂ is never mapped to NOx. Mass units or unknown units remain NaN as above. |
| `O3` | `o3` | As returned per sensor | ppb | ppb unchanged; ppm × 1000 | Mass units or unknown units remain NaN as above. |
| `CO` | `co` | As returned per sensor | ppb | ppb unchanged; ppm × 1000 | Mass units or unknown units remain NaN as above. |
| `SO2` | `so2` | As returned per sensor | ppb | ppb unchanged; ppm × 1000 | Mass units or unknown units remain NaN as above. |
| `temperature` | `temperature` | As returned per sensor | °C | °C unchanged; °F → (°F−32)×5/9; K−273.15 | Unknown units/nulls remain NaN. Values outside −100..70 °C are invalid. |
| `relative_humidity` | `relativehumidity` | As returned per sensor | % | Percent unchanged; known fraction in [0,1] × 100 | Unknown units/nulls remain NaN; values outside 0..100% are invalid. |
| `wind_speed` | `windspeed` | As returned per sensor | m/s | m/s unchanged; km/h ÷ 3.6; mph × 0.44704; knots × 0.514444 | Unknown units/nulls remain NaN; negative speeds are invalid. |
| `wind_direction` | `winddirection` | As returned per sensor | degrees | Known degree units unchanged | Unknown units/nulls remain NaN; values outside 0..360° are invalid. |

No zeros are inserted for absent measurements. CSV nulls are written as `NaN`. `data_quality_report.csv` distinguishes absent values from invalid/unsupported readings through counts and missing percentages.

## Supporting files

- `station_metadata.csv`: OpenAQ location metadata, district provenance, monitor/mobile flags, sensor lookup status, declared dates, and a `reference_priority` ordering. `selected_for_download` means at least one PM2.5 sensor exists; it does not assert sufficient observed history.
- `station_availability.csv`: per-station availability flags for each standardized variable, sensor lookup status, selected status, source ownership, and sensor IDs by variable. Treat all `has_*` flags as unknown when `sensor_lookup_status=error`.
- `sensor_metadata.csv`: all mapped sensors, parameter and source units, declared history, and the selected sensor per station-variable.
- `collection_manifest.json`: requested range, configured geographic scope, sample/full-run indicator, and downloaded station IDs.
- `data_quality_report.csv`: aggregate variable, station, and station-variable records with missing percent, row counts, observed date bounds, duplicate counts, invalid counts, and PM2.5 insufficiency flag.

## Coverage interpretation and limits

The hourly CSV uses a complete UTC time grid over each run's inclusive requested dates for stations included in that run. Missing percentage is calculated against that grid; a station created partway through the range will therefore show its early period as missing. The default minimum PM2.5 history is 720 valid hours and 10% of the run's expected hours (`OPENAQ_MIN_PM25_HOURS`, `OPENAQ_MIN_PM25_COVERAGE`), shortened automatically for the explicitly requested small sample window. This is a screening threshold, not a scientific adequacy claim.

OpenAQ only returns public observations it has ingested. If no sensor is available for a requested variable, it is marked unavailable; if a sensor exists but a returned unit cannot safely be normalized, the source value stays only in the immutable raw response. The metadata and availability report make that visible. OpenAQ licenses and attribution terms remain applicable to downstream use.

## Availability history columns (added 2026-09-30)

`scripts/data_collection/openaq/enrich_availability.py` adds three columns to
`station_availability.csv`:

- `historical_start` / `historical_end` — the earliest and latest timestamps **declared by the
  station's own sensors** in `sensor_metadata.csv`. This is source metadata, not an inference.
  Populated for 209 of 220 stations; the remainder had no parseable sensor dates.
- `observation_count_if_available` — written as the explicit marker
  `UNKNOWN (not exposed by OpenAQ v3)`. OpenAQ v3 provides no per-station record count. A count
  estimated from the date span would be a fabricated number presented as a source value, so it is
  deliberately not produced.

## Aggregation caveat

`/sensors/{id}/hours` returns precomputed hourly values, so the pipeline does not re-bin them.
Where duplicate `(station, hour, variable)` rows survive de-duplication they are reduced by the
**mean** of the duplicate readings. This is a mean of hourly means, not a mean of raw sub-hourly
samples — not mathematically identical to a true hourly mean at higher frequency. Recorded here
so the distinction is never treated as implicit.
