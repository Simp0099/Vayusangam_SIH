# Data to UI mapping

Audit snapshot: 2026-09-30. Source datasets under `data/` were inspected directly. Values labelled **REPLAY** are the existing deterministic synthetic workflow, not observations or a live forecast.

## Inventory and quality summary

| Dataset | Format / size | Content and coverage | Quality / use |
|---|---|---|---|
| `data/air_quality/air_quality_hourly.csv` | CSV, 72 rows, 9.8 KB | OpenAQ normalized hourly sample for one location (`2860223`, GK1 (Oberoi Terrace), 2026-09-28 00:00–2026-09-30 23:00 UTC); UTC timestamps | 72 unique hourly rows, no duplicate timestamps or gaps. PM2.5, temperature and RH each have 51/72 values (29.167% missing); PM10, NO2, NOx, O3, CO, SO2 and wind are 100% missing. Latest non-null PM2.5/RH/temperature is earlier than the final row. Insufficient for an NCR aggregate or regulatory AQI. |
| `station_metadata.csv` / `station_availability.csv` | CSV, 220 rows each | OpenAQ locations within configured bbox 74–80°E, 26–32.5°N; station coordinates, provider/owner, timezone, declared coverage and parameter availability | All 220 coordinates pass WGS84 range checks; all declare `Asia/Kolkata`. District is blank for all rows in this snapshot. These files describe locations and sensor availability, not current measurements. The geographic search area is wider than Delhi NCR. |
| `sensor_metadata.csv` | CSV, 2,591 rows | OpenAQ sensors and original units / declared coverage | Parameter availability: PM2.5 323, NO2 314, CO 308, PM10 305, O3 301, SO2 289, NOx 156; temperature 152, RH 153, wind speed and direction 145 each. Availability flags do not prove that normalized observations were downloaded. |
| `data/air_quality/raw/` | 4,824 JSON files, ~2.16 GiB | Raw OpenAQ location/sensor/hourly API pages, retained as source responses | Raw cache is much larger than the normalized table. `collection_manifest.json` still describes a one-station, 72-hour sample and says the hourly download is in progress; it is stale relative to the raw cache. | `demo/replay/delhi-winter-stagnation.json` and replay API | JSON generated by `SurrogateModelProvider` | Fixed-seed, 72-step prototype episode | Synthetic stations, pollutant values, fire points, transport, intervals, and drivers are explicitly replay/demo only. No validation skill is available. |

The raw OpenAQ cache must be reconciled with the collection manifest before treating it as a complete historical archive. The current processed table is the only safe normalized observation source for the dashboard.

## Dashboard behavior implied by the evidence

- Keep the 72-hour coupled forecast, inversion, coupling, plume, and synthetic scenario as a clearly marked **REPLAY** workflow.
- Offer real station metadata and the available OpenAQ hourly observations separately from replay. In observations, show actual values and gaps only; do not fill unavailable pollutants or estimate a regional AQI.
- Historical ERA5 and historical forecast products can support archive charts. Their source class and valid-time range must remain visible; neither is current weather or a current forecast.
- Mark district, station status, pollutant, alert, smoke, and verification states unavailable when there is no source evidence.
- Any later full OpenAQ normalization requires reconciling the in-progress raw download with its stale sample manifest, then rerunning the existing processor and quality validator. Preserve all source JSON.
